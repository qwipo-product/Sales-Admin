# Bug fixes: planning (`src/app/views/sales-person-planning`)

Build: `NG_PERSISTENT_BUILD_CACHE=0 npx ng build --configuration development --output-path <scratch>/dist-planning`
on Node 18. It exits 0 with no warnings or errors. No `.html` or `.scss` file in this folder was changed. Every
visible change comes from TypeScript: alert texts and when they appear, the pre-selected option, and the error labels
that already existed in the templates.

New file: `services/scoped-loader.ts` (`ScopedLoader`). It's a per-component handle on `AppLoaderService` that
remembers the exact `MatDialogRef` it opened and closes only that one. `close()` is idempotent. Every component and
dialog in this folder now opens and closes the "Please wait" loader through it, closes it in `finally`, and also
closes it in `ngOnDestroy`.

## Left as-is on purpose
- **`clearTaskFilters()` never runs**, because the Preview dialog closes with `{}`, not `taskStatus: Started`. The
  filters staying filled after "Generate Tasks" is production behaviour. Wiring it up, and making it reset the select-all
  flags, row checkboxes and the remaining arrays, is a product decision.
- **"You dont have permission , Please contact administrator"** is the same text across the whole app, so I didn't
  change it here alone. **'Error refreshing cluster customers:'** (trailing colon) is kept as it is.
- These have no visible effect, so they were left: `matSort` without sort headers, `data-label="delete"` on the Refresh
  cell, the unused "SIDENAV CONTENT HERE" sidenav, unused `selectAll`/`checkboxes` form controls, and the instant
  open/close of the loader in Preview `ngOnInit`.
- **Runtime checks to do in the browser** (I didn't use it, per the coordinator):
  - Switch Areas → Sales Person → Tasks quickly; no loader should stay.
  - Open EDIT on a mapped person; the current area should be pre-selected.
  - Update Polygon with a slightly moved copy of the area's own polygon; it should be accepted.
  - Refresh a mapped area; you should see exactly one success alert.
  - Tick 1 of 2 Tasks rows; the header checkbox should stay unchecked.

## Shared changes (status)
Items 1–3 below were applied by the lead in shared code (loader reuse, `insertDocWithId` rethrows; `getCustomerCount` still resolves `undefined` on error and Planning handles it). Items 4–5 concern production data/backend.

1. **`AppLoaderService.open()`** (`shared/services/app-loader/app-loader.service.ts`) overwrites `dialogRef` when a
   loader is already open, so the first one can never be closed. It should reuse an open dialog or reference-count,
   and ideally return the `MatDialogRef`. Planning works around this with `ScopedLoader`, which reads the public
   `dialogRef` right after `open()`.
2. **`SalesPersonService.getCustomerCount`** swallows HTTP errors and resolves `undefined`. It should rethrow.
   Planning checks `Array.isArray`.
3. **`FirestoreService.insertDocWithId`** swallows `setDoc` errors, which affects `createCluster`. It should rethrow.
   Planning reads the area back.
4. **Data (production)**: areas that were updated through the old bulk "Upload Geo Json" have `latitude`/`longitude`
   swapped in `SalesPersonClusters.coordinates`. They need a one-off swap migration (in India such docs have
   latitude > 60), or a re-upload. Otherwise their overlap/"same" checks and Refresh customer counts stay wrong.
5. **Backend**: the area link is read through `SalesPerson.clusterId`, but the UI writes only `SalesPerson.cluster {id,name}`.
   `clusterId` must stay maintained by the queue consumer. This is unchanged.

> **Later change:** `preview-dialog.component.ts` and the Tasks tab's table, date chips and count call were replaced by new features (see [../ENHANCEMENTS.md](../ENHANCEMENTS.md)). The rows above describe the fixes made while they matched production.
